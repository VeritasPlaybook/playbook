# 0. How To Use This Career Brain Trust (Jordan's notes)

This is my operating manual. I keep it short. The full system pattern is in the main guide; this file is the practical "what does future-me need to remember" version.

---

## What this Brain Trust is

A small filing cabinet of evergreen content about my career: my identity, my chronology, my roles with canonical bullets and variant framings, my skills, my big-number achievements, my education, and my cover letter archetypes. The point is that any AI tool I work with can read this folder and use it to draft tailored applications without me re-telling my story every time.

---

## Tag Glossary

Tags are the routing signal. The resume-builder skill greps the INDEX's Tags columns to decide which files to load for a given Job Description.

My working set, organized by category:

**Function tags:**
- `#Product`, `#Engineering`, `#Design`, `#Operations`, `#Strategy`, `#Leadership`

**Industry or domain tags:**
- `#DeveloperTools`, `#Platform`, `#B2BSaaS`, `#VerticalSaaS`, `#Healthcare`, `#Analytics`, `#FinTech`, `#DevOps`

**Technical tags:**
- `#AI`, `#ML`, `#API`, `#SDK`, `#Workflow`, `#Integrations`, `#NLQ`, `#EHR`

**Stage and shape tags:**
- `#Build`, `#0to1`, `#Scale`, `#Foundational`, `#Compliance`, `#HIPAA`, `#Usability`

**Seniority tags:**
- `#IC`, `#Senior`, `#Lead`, `#Group`

I add tags only when they show up in a real Job Description twice. If a tag has never been searched for, it does not belong.

## How the folder breaks down

- `INDEX.md`: routing table.
- `0 How To Use.md`: this file.
- `1 Identity.md`: headline, summary, positioning library.
- `2 Chronology.md`: master career table.
- `5 Skills.md`: aggregated skill inventory.
- `6 Achievements.md`: big-number metrics.
- `7 Education.md`: degrees, certifications, awards, languages, public profiles.
- `Experience/`: one file per role.
- `Cover Letters/`: archetypes plus Patterns and Reusable Hooks.

---

## Maintenance habits

**After every application:** run the update-brain-trust skill. It folds new framings back in and logs the application. Skipping this step is the single fastest way for this system to decay.

**Weekly review:** ten minutes on Sunday. Scan the variant framings from the last week. If one variant has been used in three or more applications, promote it to a canonical bullet.

**Quarterly audit:** every three months, re-read `1 Identity.md`. Does the headline still match what I want to be hired for? Update if it drifted.

**Chronology rule:** `2 Chronology.md` is canonical. Every Experience file's dates must match the chronology table. If they ever disagree, the chronology wins.
