# 0. How To Use This Career Brain Trust (Alex's notes)

Short operating manual for future-me.

---

## What this Brain Trust is

A small filing cabinet of evergreen content about my engineering career. The point is that any AI tool I work with can read this folder and draft tailored applications without me re-telling my story every time.

For engineering applications specifically, the cover letter is usually shorter and more pragmatic than a Product Manager letter. The code portfolio carries more weight than the prose. Even so, a tailored cover letter that mentions the right primitives (idempotency, exactly-once, sharded Postgres, gRPC service mesh) gets opened more often than a generic one.

## Acronym Definitions

- **API:** Application Programming Interface
- **AWS:** Amazon Web Services
- **CI/CD:** Continuous Integration and Continuous Deployment
- **CRUD:** Create, Read, Update, Delete
- **gRPC:** Google Remote Procedure Call (the protocol; the acronym is generally used as the proper noun)
- **IaC:** Infrastructure-as-Code
- **IC:** Individual Contributor
- **JD:** Job Description
- **REST:** Representational State Transfer
- **RFC:** Request for Comments (the engineering-design document, not the Internet standard tracker)
- **SDK:** Software Development Kit
- **SLO:** Service Level Objective
- **SQL:** Structured Query Language

## How the folder breaks down

- `INDEX.md`: routing table.
- `0 How To Use.md`: this file.
- `1 Identity.md`: headline, summary, positioning library.
- `2 Chronology.md`: master career table.
- `5 Skills.md`: aggregated skill inventory.
- `6 Achievements.md`: big-number metrics.
- `7 Education.md`: degree, certifications, open-source contributions, public profiles.
- `Experience/`: one file per role.
- `Cover Letters/`: archetypes plus Patterns and Reusable Hooks.

---

## Maintenance habits

**After every application:** run the update-brain-trust skill. Even a one-line variant framing is worth folding back in. The next role I apply to will use the same primitives.

**Weekly review:** ten minutes. Look at the variant framings from the week. If one rephrasing has been used twice, promote it.

**Quarterly audit:** every three months, re-read `1 Identity.md`. Has my positioning drifted from "Senior Backend Engineer targeting Staff" toward something else (Engineering Manager? Platform Lead?)? If the positioning has drifted, update.

**Code portfolio rule:** whenever I ship something publicly shareable, add a link to the relevant Experience file's Reusable Phrasings section. Code links are the asset cover letters lean on most.
