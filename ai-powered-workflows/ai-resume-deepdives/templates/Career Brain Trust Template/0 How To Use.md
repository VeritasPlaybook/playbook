# 0. How To Use This Career Brain Trust

This is your operating manual. Read it once. Refer back to the Tag Glossary and Acronyms sections as needed.

---

## What this Brain Trust is

A structured folder that holds everything your AI needs to know about your career, written in your own voice, organized so that a Job Description can be matched against it programmatically.

You are not writing a single document. You are building a small filing cabinet of evergreen content. Each file is small, focused, and tagged. The skills that run against this folder read only what they need, when they need it.

When the resume-builder skill runs, it reads this INDEX, picks the three or four most relevant Experience files and the one to three most relevant Cover Letter archetypes by tag match, and uses only those to draft your tailored application. Everything else stays out of working memory.

---

## How to fill this in

Three options, pick whichever feels right for you:

1. **Manual.** Open each file in this template and fill in your own content. Slowest but most deliberate. Useful if you want to think your career through one file at a time.
2. **Setup prompt.** Paste the `Career Brain Trust Setup Prompt.md` from the Templates folder into a fresh AI thread. Answer the interview questions. The AI builds your Brain Trust by interview, file by file. Fastest path to a usable version one.
3. **Reference an example.** Open one of the three example filled Brain Trusts (PM Jordan, Engineer Alex, Marketing Sam) in the Templates folder and use it as a model while you build yours. Useful as a guide even if you build from scratch.

Whatever path you pick, the goal is a working version one. You can always refine over time as the update-brain-trust skill folds new framings back in.

---

## Tag Glossary

Tags are the routing signal. The resume-builder skill greps the INDEX's Tags columns to decide which files to load for a given Job Description.

Good tags share two properties: they are specific enough to discriminate (so a Tag match actually means something), and they are general enough to recur (so the same Tag appears in multiple files when relevant).

Start with a small set. Add tags as you discover patterns. A common starter set:

**Function tags** (what you do):
- `#Product`, `#Engineering`, `#Marketing`, `#Sales`, `#Design`, `#Operations`, `#Strategy`, `#Leadership`

**Industry or domain tags** (where you do it):
- `#FinTech`, `#Banking`, `#Payments`, `#Fraud`, `#SaaS`, `#DeveloperTools`, `#Marketplace`, `#Healthcare`, `#Climate`, `#Government`, `#Media`

**Technical tags** (what you ship with):
- `#AI`, `#ML`, `#LLM`, `#API`, `#Mobile`, `#Web`, `#Platform`, `#Cloud`, `#Data`, `#Analytics`

**Stage and shape tags** (what kind of work):
- `#Build`, `#0to1`, `#Scale`, `#Turnaround`, `#GTM`, `#Compliance`, `#Regulatory`

**Seniority tags** (what level the role implies):
- `#IC`, `#Manager`, `#Senior`, `#Lead`, `#Director`, `#VP`, `#Head`

Use whatever feels natural. Keep them consistent. Update this glossary as you go.

## Acronym Definitions

The first time an acronym appears in any cover letter or resume, spell it out in full followed by the acronym in parentheses, then use the acronym for the rest of that document. This is the layered reinforcement pattern: it lowers the reader's cognitive load without making the document feel patronizing.

A working list of common acronyms in this template:

- **AI:** Artificial Intelligence
- **ML:** Machine Learning
- **AI/ML:** Artificial Intelligence and Machine Learning
- **ATS:** Applicant Tracking System
- **CC BY 4.0:** Creative Commons Attribution 4.0
- **JD:** Job Description
- **PDF:** Portable Document Format
- **PLG:** Product-Led Growth
- **PM:** Product Manager
- **SaaS:** Software-as-a-Service

Add your own specialized acronyms here as they appear in your industry (e.g., `PCI-DSS`, `FINTRAC`, `ACAMS`, `OKR`, `RACI`). Defining them once in the glossary lets your AI consistently spell them out the first time in every document it generates.

## How the folder breaks down

A short tour of the files in this template:

- `INDEX.md`: the routing table. The skills read this first to decide what else to load.
- `0 How To Use.md`: this file. Operating manual.
- `1 Identity.md`: your headline, summary, and a library of alternate positioning statements.
- `2 Chronology.md`: the master career chronology in one place. Dates, titles, employers.
- `5 Skills.md`: aggregated skill inventory across function, domain, technical, leadership.
- `6 Achievements.md`: the big-number metrics. Deduplicated, organized by employer, with sources.
- `7 Education.md`: degrees, certifications, awards, languages, public profile links.
- `Experience/`: one file per role you've held. Canonical bullets plus variant framings.
- `Cover Letters/`: one file per archetype (banking, startup, big tech, etc.) plus Patterns and Reusable Hooks.

The numbered prefix on file names is just for visual ordering inside the folder. The skills do not care about the numbers; they care about the Tags columns in the INDEX.

---

## Maintenance habits

The Brain Trust is a living document. A few habits keep it sharp:

**Weekly review:** ten minutes on Sunday or Friday. Scan the variant framings that landed in the last week. Promote anything that consistently lands to a canonical bullet. Demote anything that never gets used.

**After every application:** run the update-brain-trust skill. It folds new framings back into the source of truth and logs the application. Skipping this step is the single most common failure mode.

**Quarterly audit:** every three months, re-read your `1 Identity.md`. Does the headline still match what you want to be hired for? Update if it drifted.

**Never edit the chronology in two places.** `2 Chronology.md` is canonical. Every Experience file's dates must match the chronology file. If they ever disagree, the chronology wins.
